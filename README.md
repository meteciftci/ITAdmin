# ITAdmin

ITAdmin is an enterprise IT administration portal for Active Directory operations, identity and
permission management, notifications, licensing, audit, and security monitoring. The backend is
ASP.NET Core, the frontend is React/TypeScript, and production runs on IIS with PostgreSQL.

## Production installation

There is no release packaging, no version tags, and no separate distribution artifact. Production
runs from a clone of this public repository, built on the server itself.

Prerequisites on Windows Server 2022/2025 (elevated PowerShell):

- [Git for Windows](https://git-scm.com/download/win)
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- [Node.js 20+ (LTS)](https://nodejs.org/) with npm
- IIS, and the [ASP.NET Core 10 Hosting Bundle](https://dotnet.microsoft.com/download/dotnet/10.0)
  (ASP.NET Core Runtime → Hosting Bundle)

Then:

```powershell
git clone https://github.com/meteciftci/ITAdmin.git C:\ITAdmin\src
C:\ITAdmin\src\scripts\deploy\Deploy-ITAdmin.ps1 -InstallIisFeatures
```

`Deploy-ITAdmin.ps1` is the single engine for both first install and every later update: it checks
prerequisites, builds the backend (`dotnet publish`) and the frontend (`npm ci && npm run build`),
provisions the database and the application's login role, applies migrations, establishes the first
directory-backed administrator, and points IIS at the fresh build. There is no in-application setup
wizard.

PostgreSQL must already be running and reachable — that is the only database precondition. The
script creates its own database and its own least-privilege login role: the operator supplies the
application role name and a PostgreSQL administrator credential (superuser, or a role with
`CREATEROLE` and `CREATEDB`) that is used only for that one step, written to an ACL-restricted file
that is deleted immediately, and never stored. The application role's password is generated by the
script, kept in the DPAPI machine secret store, and shown once at the end of the run.

See [the exact first-install procedure](docs/first-install.md) and
[deployment/update architecture](docs/deployment.md).

## Updating

Pushed a change to `main`? Re-run the same script on the server — it fetches the branch tip,
rebuilds, migrates, and activates, keeping the previous build on disk for rollback:

```powershell
C:\ITAdmin\src\scripts\deploy\Deploy-ITAdmin.ps1
```

```powershell
# Undo the last activation if a build looks wrong. Database migrations are forward-only and are
# NOT reversed.
C:\ITAdmin\src\scripts\deploy\Deploy-ITAdmin.ps1 -Rollback
```

The same update can be triggered from inside the application (**Settings → Updates**, permission
`System.Updates.Manage`). The LocalSystem ITAdmin Host Agent applies it by running this same script
on the server; the web application never gains build, deployment, or filesystem privilege.

## Local development

Create the ignored local environment file, start PostgreSQL/API, and start the frontend:

```bash
cp .env.development.example .env.development
./scripts/dev/start-backend.zsh
```

```bash
cd frontend
npm ci
npm run dev
```

There is no in-application setup wizard. To make a fresh local database logged-in-able, fill the
`ITADMIN_DEV_LDAP_*` / `ITADMIN_DEV_INITIAL_ADMIN` values in `.env.development` and run once:

```bash
./scripts/dev/bootstrap-directory.zsh
```

This drives the same `ITAdmin.Api.exe --bootstrap-directory` path the deploy script uses, so it
needs a reachable LDAP/AD.

Useful validation commands:

```bash
dotnet test backend/ITAdmin.slnx
cd frontend && npm run lint && npm run test:unit && npm run build
```

## Security and operations

- Authentication is Active Directory-backed; authorization is permission-based and enforced by the
  backend.
- Runtime secrets are DPAPI LocalMachine-protected under `%ProgramData%\ITAdmin\secrets`.
- ASP.NET Data Protection keys under `%ProgramData%\ITAdmin\DataProtection-Keys` are
  infrastructure-critical and must be backed up with the database.
- Initial installation uses HTTP so certificate issuance cannot block commissioning. Configure
  HTTPS with `Deploy-ITAdmin.ps1 -ConfigureHttps` after login; do not treat HTTP as a steady state.
- The IIS application pool never receives build, deployment, or LocalSystem privilege — that stays
  with the ITAdmin Host Agent, a separate Windows service reachable only over an ACL'd local named
  pipe.
- Audit and security logs are part of the operational record. Host-level update detail stays in the
  Host Agent/Update Coordinator logs and sanitized status is returned to the web application.
